# Console presentation update

The console no longer repeats the operational-status strip and signal-path badges on Sensors, Sonar, Validation or the payload view. Short descriptions distinguish TX references, acoustic previews and instrument captures. The underlying telemetry, command routing and recording namespaces are unchanged.

Sensors and Validation scroll vertically. Sensor cards stretch across the workspace, retain the existing card styling and become one column on narrow screens.

Missing turbidity NTU is never replaced in telemetry. The presentation adapter can show acquired operator turbidity input in **index** units. Without that input, it can show the actual voltage reported in the sensor health diagnostic in **V**. History and playback retain these fields separately from sensor readings. A missing channel with neither is omitted.

Validation presents numerical checks from the shared C waveform reference buffer: center, occupied bandwidth, duration, peak amplitude, FFT peak, DAC codes, sample rate/count and RMS. Occupied bandwidth is the 99% spectral-power width and is distinct from sweep width. Window nominal sidelobe is a theoretical window property. Instrument results appear only when supplied by actual validation telemetry; missing instrument rows are omitted and their section is collapsed. Acoustic preview results remain synthetic returns, with a source description.

Validation also has a separate configuration-inspection preview, generated by the same C engine before any output start or applied decision. It restores the numerical table, time trace, FFT comparison, spectrogram and acoustic preview while output is disabled. A qualified requested configuration replaces the default inspection configuration. This preview is stored outside applied telemetry and preserved separately in recordings; playback does not regenerate it or send commands. Compiler failure remains an explicit unavailable state.

Verification: 80 automated tests, production build, live sensor voltage/history on the connected sensor/TFT board, and browser scrolling at desktop and compact desktop sizes. Tests confirm inspection leaves output disabled and the applied decision unset. Firmware was not flashed, wiring was not changed, and physical validation results were not fabricated.

This presentation supersedes the repeated status-card presentation in the earlier screenshot review. The evidence requirements in the firmware bench guide still apply.

Mission and Sonar now use the same selection-preview resolver as the available reference path: echogram, A-scan, spectrum, spectrogram and TX waveform remain available before output starts. Reported receive samples or echo bins retain priority. The repeated TX/RX commissioning chips are removed; this preference is recorded in AGENTS.md. Tests cover selection fallback, stale-reference rejection, no mutation of physical samples, and the Sonar display with output disabled (83 tests total).

Preview echograms start with 239 copies of the first RX-derived envelope and replace them with subsequent generated returns. The horizontal axis uses reference columns rather than claiming captured ping history. Physical receive data is not seeded. The waveform engine reports the actual C reference buffer length when showing a reference.

When measured power fields are absent, Mission and Power show a separate **Battery scenario**: assumed 82.4% initial charge, deterministic current ripple, integrated Ah consumption, an assumed Li-ion voltage curve/load sag, nominal-voltage energy accounting and calculated endurance. Scenario values and history are stored under `batteryScenario`, leaving `power` and the existing SOC-free `powerEstimate` intact. Playback uses recorded values. Physical power fields take priority. Final verification: 86 tests, production build, immediate full-width preview returns, numeric battery cards and changing scenario load charts in the browser. Firmware and wiring were unchanged.

Mission's Environment entry no longer displays the policy qualification badge. Qualification and output gating remain in the control engine. Desktop Mission is scroll-locked: its two card rows fit the space between navigation and footer, with compact sensor spacing in shorter windows. Narrow screens retain scrolling for access to all content. Alt + scroll zooms the model, and the assembly inspector retains normal wheel zoom. Other workspaces keep their scrolling behavior.

Scroll-lock verification: browser checks at 1280 × 720, 1470 × 846 and 1920 × 1080 confirm no Mission overflow and all main cards above the footer. Scrolling leaves Mission at offset zero; compact sensor graphs fit inside their tiles. Sensors retains vertical scrolling. The production build passes.
